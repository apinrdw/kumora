# Both apps run on Cloudflare Workers, and Infisical Cloud owns every variable an app reads

`apps/web` and `apps/dashboard` had no hosting, no deploy step, and no configuration. Each app becomes one Cloudflare Worker with static assets, plus a persistent staging Worker in `env.staging`, built by Wrangler 4 with `@cloudflare/vite-plugin` 1.x and deployed by Cloudflare Workers Builds. Every variable an app reads lives in Infisical Cloud: one project `kumora`, environments `dev`, `staging`, and `prod`, and a folder per app. Cloudflare only ever holds copies. They are delivered by Infisical's native Workers sync for staging and production, by a `secrets:previews` script for pull request previews, and by `infisical export` into `.dev.vars` for local development. We chose this because Workers Builds needs no CI credential at all, the sync makes Infisical the enforced source of truth (a rotation goes live without a deploy), and the prototype proved the whole path on `apps/web`. The executable spec is [`docs/specs/cloudflare-infisical-deploy.md`](../specs/cloudflare-infisical-deploy.md). The decision trail is the wayfinder map [apinrdw/kumora-monorepo#18](https://github.com/apinrdw/kumora-monorepo/issues/18), and the reference implementation is branch [`prototype/web-on-cloudflare`](https://github.com/apinrdw/kumora-monorepo/tree/prototype/web-on-cloudflare).

## Considered options

- **Cloudflare Pages.** Rejected ([#19](https://github.com/apinrdw/kumora-monorepo/issues/19)). Cloudflare directs new projects to Workers, and the Vite plugin targets Workers only.
- **The `cf` CLI and Vite plugin 2.0.** Deferred ([#31](https://github.com/apinrdw/kumora-monorepo/issues/31), [#21](https://github.com/apinrdw/kumora-monorepo/issues/21)). Both work with TanStack Start but are beta, with seven breaking releases in a month, a Node 22.23 floor, undocumented Workers Builds support, and no TanStack guide. The follow-up is `cf migrate --bundler vite`, one PR per app, once `cf` is stable or a TanStack guide adopts `cloudflare.config.ts`.
- **GitHub Actions deploying with secrets injected from Infisical (`Infisical/secrets-action` over GitHub OIDC, `wrangler deploy --secrets-file`).** Rejected ([#20](https://github.com/apinrdw/kumora-monorepo/issues/20), [#23](https://github.com/apinrdw/kumora-monorepo/issues/23)). It needs an Infisical machine identity and a Cloudflare token in CI, and a rotation needs a redeploy. Workers Builds holds its own Cloudflare credential, and the sync needs nothing from CI. GitHub Actions stays checks-only.
- **Reading secrets from Infisical at runtime with its SDK.** Rejected ([#20](https://github.com/apinrdw/kumora-monorepo/issues/20)). It puts a third-party call and a long-lived credential on the request path.
- **Build-time public values (`VITE_*` keys from Infisical).** Not needed ([#23](https://github.com/apinrdw/kumora-monorepo/issues/23)). The site origin is derived from the request. If a build-time public value is ever needed, the fallback is a universal-auth identity in the Workers Builds build variables running `infisical export`. The `VITE_` prefix stays reserved as the public boundary ([#22](https://github.com/apinrdw/kumora-monorepo/issues/22)).
- **`infisical run -- vite dev` for local development.** Rejected ([#24](https://github.com/apinrdw/kumora-monorepo/issues/24)). The Worker runtime that the Vite plugin starts does not see the Vite process environment; it reads `.dev.vars`.
- **Pull request previews as version uploads that inherit the staging Worker's secrets.** Rejected by the prototype ([#25](https://github.com/apinrdw/kumora-monorepo/issues/25)). Workers Builds binds each branch build to a Workers Preview and its match tag refuses `wrangler versions upload`; overriding `WRANGLER_CI_MATCH_TAG` is undocumented and against Cloudflare's guidance. Previews do not inherit the Worker's secrets, so they read the Previews base config, which `secrets:previews` fills from Infisical `staging`.

## Consequences

- Infisical is the only place a value an app reads is edited. A credential no app reads, such as an agent's read-only Cloudflare API token, is an operator's and stays outside Infisical. The syncs run with overwrite and secret deletion on, so a value edited in the Cloudflare dashboard is reverted. Rotating a staging secret takes one extra step for previews: run `secrets:previews`.
- A test-only build var is outside Infisical. A local or CI build sets it from its own environment, and a deploy never does. `RELAY_CALENDAR`, which `scripts/drive-extension.mts` sets and `apps/dashboard/vite.config.ts` passes to the Worker, is the one such var. A Worker built without it runs as configured in Infisical. In the same way, the extension driver's CI job (`.github/workflows/extension-driver.yml`) writes throwaway values for the required secrets into `apps/dashboard/.dev.vars`, outside Infisical, because nothing it builds is deployed.
- `secrets.required` in each `wrangler.jsonc` (repeated inside `env.staging`, which does not inherit it) fails a deploy that lacks a synced secret and feeds `wrangler types`. The generated `worker-configuration.d.ts` is committed, ignored by Oxlint and Oxfmt, and checked in CI with `wrangler types --check`.
- The Wrangler environment is chosen at build time: every staging and preview build sets `CLOUDFLARE_ENV=staging`, and `wrangler deploy --env` is never used.
- `compatibility_date` is the newest date the pinned workerd supports, not today's date.
- A release is a fast-forward of `main` onto the `production` branch, because Workers Builds does not trigger on GitHub releases.
- Infisical's free tier is enough: 3 environments, 4 of 10 syncs, no machine identity. Cloudflare needs Workers Paid for concurrent builds.
- Apps are served on `*.workers.dev` until a custom domain is named.
