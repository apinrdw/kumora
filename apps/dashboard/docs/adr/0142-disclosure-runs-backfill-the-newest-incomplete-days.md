# Disclosure runs backfill the newest incomplete days

The disclosure archive reaches back to IDX's first disclosure day, 3 July 2023 (~269k disclosures, ~600k files, ~130 GB), with no backfill action of its own. Each disclosure run lists the recent days first, the last RECENT_DAYS (`disclosure-day.ts`), and stores what they wait for. What is left of its budget of FILES_PER_RUN attachments (`archive-run.ts`) goes to the older days that aren't complete, newest first. Days a run has already begun come first: each listed after it ended that still has attachments waiting, newest first, is taken up as the index holds it. Then the run walks back from the day before the recent days toward the first day. On that walk, a day listed after it ended is taken up as the index holds it, and any other day is listed first. The run takes up days until their waiting attachments fill the budget, at most MAX_BACKFILL_DAYS a run. The `files:` steps store the days' attachments in the order the run took the days up, and within a day the newest disclosure's first. A day older than the recent days becomes complete when a run has listed it after it ended and none of its attachments waits. ArchiveDb records when (`disclosure_day.complete_at`, `archive-migrations/0006_disclosure_day_complete.sql`), and no run lists it again. A run whose days still wait when its budget is spent ends partial, as one with a failed download does, and the next run takes those attachments up first, before listing another day. Only a recent day's listing that can't be read fails a run. An older day's listing is left as it was: the run names the day and IDX's answer on its record (`unlistedDays`), takes up the day before it, stores the recent days' attachments and ends partial, and the next run lists that day again. Failing the run there would leave the recent days unstored for as long as IDX can't serve that day. The run record's `backfillDays` and `unlistedDays` name days in the order the run took them up. At one run every 15 minutes, 96 budgets a day, the history is stored in about a week.

Walking newest first puts the disclosures a reader is likeliest to open into the archive first, while the history fills in behind them. This replaces ADR 0138's oldest-first walk. Taking up begun days first keeps the days an earlier run left half-stored, the oldest-first walk's among them, from waiting until the walk reaches them again, which could take days. The walk itself was the alternative: a begun day would wait in place. A day whose waiting attachments all keep failing still goes first, since it costs the budget only its waiting count, and ADR 0139 makes those attachments unavailable after 7 days. A backfill action or a separate cursor was another alternative: the spec wants one kind of run, and the index already says which days are complete. Reporting a run out of budget as complete would hide that the archive is still behind. The coverage by day shows how far behind.
