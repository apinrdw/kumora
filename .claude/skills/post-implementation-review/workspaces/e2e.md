# e2e

Running the Playwright suite against the Test stage.

- **Parallel runs share only the CPU.** Ports are per run unless both runs export the same one (`apps/e2e/support/ports.ts` says how a preset one is treated); give each run `--workers=<cores / runs>`: two runs at 8 workers on 16 cores time out sign-in specs.
- **`vp run test:e2e tests/<file>.spec.ts` still runs the setup project**, which signs up and verifies the shared accounts from `.eml` files first, so a one-spec run takes about 40 s.
- **Each browser context needs its own client IP.** Import `test` and `newClientContext` from `support/test.ts`: it sends a random `cf-connecting-ip` per context, so the per-IP rate limits stay on without specs eating each other's budget. A spec that builds a context with `browser.newContext` directly shares one IP.
- **The whole suite runs in CI; evidence is video only.** `.github/workflows/e2e.yml` runs it on every ready PR that touches app code, one job per project or `--shard` of one, and its `e2e` job is the required check; a red job uploads its traces as an artifact. Run `vp run e2e:evidence <spec...>`, naming the specs whose videos show the change: it runs setup and those specs alone and posts their video, which sets `e2e-evidence`. It needs a gh recent enough for `gh pr comment --attach` (`GH_MINIMUM` in `scripts/e2e-evidence-plan.mts`). A PR with no visible behaviour change takes the `no-e2e-evidence` label instead.
- **A red run posts nothing.** Fix the failure it prints and run it again. What else it refuses, and why, is in `scripts/e2e-evidence-plan.mts`.
- **Which tests record video is set in `apps/e2e/playwright.config.ts`.** Split a long journey into tests with their own accounts rather than raising the 30 s default timeout.
- **A timing fix needs a slow server to plant against.** `if (message._tag === "Frames") yield* Effect.sleep(Duration.millis(1_500))` before `market.ingest(message)` in `apps/dashboard/src/server/market-live/trading-day.ts` makes the recorded specs' pre-fix waits fail (`Expected: 5, Received: 0`).
- **A Durable Object's real platform limits only show in e2e.** Unit tests' fake socket attachment has no 16,384-byte cap, so a defect that overflows it passes every vitest suite; the Test stage's workerd refuses it ("A WebSocket 'attachment' cannot be larger than 16384 bytes").
- **Print the URLs a run would use with `bun`, not `node`.** From `apps/e2e`, `KUMORA_WEB_PORT=4567 bun -e 'const a = await import("./support/accounts.ts"); console.log(a.testUrl("web"), a.DASHBOARD)'` prints them; plain Node fails with `ERR_MODULE_NOT_FOUND` on the extensionless `./ports` import.
- **Trades stamped in the past leave their feed DELAYED for later specs.** The trading-day object times each relayed trade against the market clock (`feed-lag.ts`), and the market-live specs share one trading-day object. Three or more past-stamped trades in a 10 s window, such as trades at a fixed `10:00:01` sent once the run has gone past 10:00:06 on the Test clock, turn that feed delayed, and it stays delayed until on-time trades bring its median lag under 2 s or it goes stale (`feed-health.ts`). A test that expects LIVE sends trades stamped `wibTime(marketNow())`, as `session1Today()` in `support/ingest.ts` does.
- **A spec that reads a stored minute's trades stamps them now.** Every spec numbers its trades above the last one's (`freshTradeNumbers`), and the day store finds a minute's trades by a search that takes trade numbers to run in time order (`highestWithin` in `apps/dashboard/src/server/market-live/day-store.ts`). A sweep brokers recompute reads a minute that way, so sweeps stamped a minute back lose their brokers when the search reads an earlier spec's lower-numbered, later trade: one full run in PR #349 failed so, while the spec passed alone. The comment on the second test's stamp in `tests/market-live-sweeps.spec.ts` says why.
- **Run one project alone with `E2E_PROJECTS`.** Naming a spec of a project that waits on others runs every project it waits on, which is the whole suite. `E2E_PROJECTS=repaint-bench vp run test:e2e` runs setup and that project alone, still after setup, as each CI job does (`apps/e2e/support/projects.ts`); `--project=setup --project=<p> --no-deps` drops that order, and cold-day at `--workers=4` then races the account setup and fails with a 401. A repaint bench run beside another worktree's e2e can read 17 ms on chart 1; rerun it alone before calling a regression. CI never runs the bench (its bar is the dev machine's CPU), so a change to the charts' paints runs it here.
- **A reload-from-cache check counts only answered GETs.** The dev build mounts a page twice and the second mount cancels the first one's GETs; under load the cancel lands before the cache hit, so Chromium reports them `net::ERR_ABORTED` with no response, not cached. Spec #556's first evidence run failed so (`cold-day.spec.ts`), while the spec passed alone; read the trace's network entries for status -1 before suspecting the cache headers.
- **A new recorded-day GET joins `cold-day.spec.ts`'s reload list.** Its reload test expects the exact set of resources a cold day's reload asks for, then checks each came from the browser's cache. Spec #605's `order-flow-events` GET failed the first evidence run there (`+ "order-flow-events"`); add the resource to that set, and the cache assertion after it proves the new GET is kept.
- **A repaint bench failure may be its setup, not its repaints.** On spec #605 it failed waiting 5 s for `data-heatmap-slices` (`Received string: "0"`) under a full run's load; alone it passed at 10.7 ms candles p95. Read which assertion failed before reading it as a regression.
- **Never assert hydration inside a reload retry.** A `toPass` that reloads and then waits 1 s for a button `useHydrated` disables fails every retry under an evidence run's load, though it passes alone. Check the stored outcome inside the loop and the enabled button after it (spec #673's `holder-moves.spec.ts`).
- **`market-bubbles.spec.ts`'s sector-label click is flaky.** On spec #673 it clicked "Unclassified" for "Energy" once in a full run and in 3 of 3 `--repeat-each=3` runs alone, then passed alone; the branch did not touch Market bubbles.
- **A relay test waiting on `streaming-hours` moves the relay clock into Session 1 before it saves a setting.** A tick into Streaming hours starts no run, so a test that moved the clock after its settings waited on runs the real clock started; under `--workers=4 --trace=retain-on-failure` they had all ended on `no-tab` first (#731). A fake broker answer matches the real one's row order too: Ajaib's Done Details rows come newest first, and the walk pairs them in that order (#760).
- **`vp run e2e:evidence` takes spec file paths, not project names.** `vp run e2e:evidence holder-map` fails before Playwright starts (`E2E_VIDEO=…: no spec file under apps/e2e/tests is holder-map`); name `apps/e2e/tests/holder-map.spec.ts`.
- **A project in its own CI job starts from empty stores.** On one machine, a project that waited on `chromium` inherited what `chromium` specs left in the local databases: `stocks.spec.ts`'s seeded Jul 2026 above-1% month hid a TRUE Off list move only in full runs (spec #733). CI's jobs no longer see that; to reproduce such a run, keep the dependencies: `vp run test:e2e --project=setup --project=chromium --project=<p> --workers=4 <spec files>`.
