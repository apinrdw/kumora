# e2e

Running the Playwright suite against the Test stage.

- **Parallel runs share only the CPU.** Ports are per run unless both runs export the same one (`apps/e2e/support/ports.ts` says how a preset one is treated); give each run `--workers=<cores / runs>`: two runs at 8 workers on 16 cores time out sign-in specs.
- **`pnpm test:e2e -- <file>` still runs the setup project**, which signs up and verifies the shared accounts from `.eml` files first, so a one-spec run takes about 40 s.
- **Each browser context needs its own client IP.** Import `test` and `newClientContext` from `support/test.ts`: it sends a random `cf-connecting-ip` per context, so the per-IP rate limits stay on without specs eating each other's budget. A spec that builds a context with `browser.newContext` directly shares one IP.
- **e2e runs only on the dev machine; CI checks for evidence.** The `e2e-evidence` commit status stays red on each new PR head until `pnpm e2e:evidence [--pr <n>] [--dry-run] [spec...]` posts for it. It passes without a run when the PR touches no app code or carries the `no-e2e-evidence` label, which suits a change with no visible behaviour.
- **Name the specs that show the change.** `pnpm e2e:evidence market-live-select.spec.ts` posts that file's videos, one per test, plus every spec file the branch changes against the PR's base as last fetched. With none named and none changed it refuses: name one, or label the PR. The full suite runs either way.
- **Evidence needs a clean tree, `HEAD` on the PR's pushed head, an open PR and gh 2.99.0 or later** (the first with `gh pr comment --attach`). The command refuses on any of these and prints every unmet one. `--dry-run` runs past all but the PR and the selection, posts nothing and prints the comment and gh calls, so it is how to try the run on an older gh.
- **What blocks a post.** Any failed test, picked or not, a picked spec that ran no test, or a video over 100 MB. The command posts nothing, leaves the status alone, prints each failure with its local video and trace paths and exits 1.
- **The evidence run takes about a quarter of the cores.** Every page records through its own VP9 encoder, so it passes `--workers=<cores / 4>`: on 16 cores, 8 workers with video timed out `account.spec`, 4 passed. Run nothing else CPU-heavy beside it, and split a long journey into tests with their own accounts rather than raising the 30 s default timeout.
- **A timing fix needs a slow server to plant against.** `if (message._tag === "Frames") yield* Effect.sleep(Duration.millis(1_500))` before `market.ingest(message)` in `apps/dashboard/src/server/market-live/trading-day.ts` makes the recorded specs' pre-fix waits fail (`Expected: 5, Received: 0`).
- **A Durable Object's real platform limits only show in e2e.** Unit tests' fake socket attachment has no 16,384-byte cap, so a defect that overflows it passes every vitest suite; the Test stage's workerd refuses it ("A WebSocket 'attachment' cannot be larger than 16384 bytes").
- **Print the URLs a run would use with `bun`, not `node`.** From `apps/e2e`, `KUMORA_WEB_PORT=4567 bun -e 'const a = await import("./support/accounts.ts"); console.log(a.testUrl("web"), a.DASHBOARD)'` prints them; plain Node fails with `ERR_MODULE_NOT_FOUND` on the extensionless `./ports` import.
