# dashboard

Driving the shell in a real browser.

- **Stop servers by port with `fuser -k 3001/tcp`.** A `pkill -f` pattern that also appears later in the same shell command kills that shell, with exit 144.
- **Every page sits behind the sign-in gate.** Signed out, `curl -sS -o /dev/null -w '%{http_code} %{redirect_url}' <url>/` answers `307 …/sign-in?redirect=%2F`; that is the quickest check that a stage serves the gate (a Preview too). Signed in, `/` is still the not-found page inside the shell until Market Live exists.
- **The Test stage needs `ADMIN_EMAILS` in the process environment.** `ALCHEMY_STAGE=test ADMIN_EMAILS=admin@example.com bun alchemy dev` runs with no Cloudflare or Infisical credential; `pnpm test:e2e` sets it for you. The Dev stage (`pnpm dev`) reads it from Infisical `staging` and fails until it is there.
- **Mail lands as `.eml` files** under `apps/dashboard/.alchemy/local/email`, newest last; the links in them are the only way to verify an account locally.
- **Turnstile's iframe isn't reachable by selector.** On 2026-11-07, `iframe[src*="challenges.cloudflare.com"]` matched nothing on `/sign-up` (probably a shadow root, not confirmed); check instead that the form's request to `/api/auth/sign-up/email` carries an `x-captcha-response` header (Turnstile's test keys pass every token).
- **Plant a defect against the handler seam.** `pnpm exec vitest run tests/server/auth/<file>.test.ts` from `apps/dashboard` runs real Better Auth over SQLite in seconds; most auth fixes are covered there, not only in e2e.
- **Port 3000 or 3001 taken by another project?** Both dev ports are strict. For a hand-run `bun alchemy dev`, set the port variables (`DEV_PORT_VARIABLES` in `packages/deploy/src/target.ts`). `unshare -rn` also gives a private loopback but no internet, and sign-up loads Turnstile from Cloudflare, so e2e's account setup times out there; it only suits a server you drive without signing up. `pnpm test:e2e` needs neither (`apps/e2e/support/ports.ts`).
- **Run one e2e test from `apps/e2e`.** `pnpm exec playwright test tests/<file>.spec.ts -g "<title>"` runs it after the setup project, without rebuilding the extension as `pnpm test:e2e` does. The dashboard entry has `reuseExistingServer` on, so a leftover server on the run's dashboard port is reused; `apps/e2e/support/ports.ts` says how that port is chosen.
- **A search param a route's `validateSearch` drops stays in the URL.** TanStack keeps keys the validator leaves out, so dropping `sort` in `parseAccountSearch` is no plant for "sort lives in the URL"; drop it from the navigation instead (the page's `onSearch`).
- **The dashboard has no `/probe`; check a Preview's Market Live gate signed out.** `curl <url>/market-live/days` and `<url>/market-live/days/<date>/candles/<code>` must answer `401` JSON with `cache-control: no-store`; `node -e 'const w=new WebSocket(process.argv[1]);w.onclose=e=>console.log(e.code)' wss://<host>/market-live/live` must print `4401`. A malformed day or code falls through to TanStack Start's `307` to sign-in.
- **Planting a fix that later rounds rewrote.** `git show <green> -- <src> | git apply -R` fails once later commits touch the same lines; never fall back to `git apply -3` in a loop, since it leaves unmerged paths that `git checkout -- .` can't clear. Write the defect by hand as a patch against the head, keep every export the test imports (a missing export fails as a TypeError, which proves nothing), and reset with `git reset --hard HEAD` between plants.
- **A Preview's ingest socket must close a silent client.** `node -e 'const w=new WebSocket(process.argv[1]);const t=Date.now();w.onclose=e=>console.log(e.code,Math.round((Date.now()-t)/1000))' wss://<host>/market-live/ingest` prints `4408` after about 20 s on Cloudflare; the local Test stage's alarms run later, so its e2e took about 39 s.
- **Two guards can mask one plant.** When a later round adds a second check for the same defect (round 21's auction rule over round 12's day filter for indicative prices), reversing only the older fix passes its test; record it as layered, not as a missing test.
- **Probe a Preview's broker codes route with curl.** `bun packages/deploy/src/teardown.ts stage <branch>` prints the stage, so the host is `kumora-dashboard-<stage>.kumora.workers.dev`. An `OPTIONS` to `/api/broker-codes/<date>` answers `204` with `access-control-allow-origin: *`, and a wrong bearer answers `401` with the same header and `cache-control: no-store`. A bad date also answers `401`, because the token is checked first.
- **Plant a tape clipping defect on the columns, not the panel.** A `table-fixed` table grows to the sum of its explicit `<col>` widths, so narrowing Market Live's tape panel back to 400px leaves nothing clipped (it scrolls instead). Give Price, Lot and Value auto `<col>`s in `tape-list.tsx` and the e2e clip check in `market-live-recorded-day.spec.ts` fails, naming the clipped cells.
- **Plant a pan-sync defect against the fake-chart Vitest, not the e2e.** `tests/components/market-live/chart-pair.test.ts` drives `chart-pair.ts` with a fake Lightweight Charts time scale, so a planted "hover leads" or missing first-range read fails in seconds with the drifted range (`expected { from: 53, to: 62 } to deeply equal { from: 52, to: 61 }`); the e2e pan specs only catch it on some runs.
- **Plant heatmap drawing defects against `tests/components/market-live/book-heatmap.test.ts`.** It runs `attachBookHeatmap` with the real heatmap store and replay cursor and fakes only the chart and canvas, so a slice's left edge and the count of cached canvases are plain assertions.
- **Find a parser guard's test by its message, not its folder.** The holdings parsers' row guards (no SHARE CODE, numeric code, blank KSEI Code) are tested in `tests/server/shareholding/classification-parse.test.ts` and `tests/server/ksei/parse-run.test.ts`, not under `tests/server/holdings`; grep the tests for the refusal message before calling a plant untested.
- **Heap plants fail without an assertion.** The bounded-heap parse tests (`tests/server/holdings/bounded-heap.ts`) report a planted memory defect as `Worker terminated … JS heap out of memory` or a 30 s timeout; a full `tests/server/holdings` run takes about 60–70 s.
- **A new `holdings-migrations/*.sql` is invisible to Vitest until `pnpm exec vitest run --clearCache`** from `apps/dashboard`; until then the server tests fail with `no such table`. Spec #402's investor-type migration hit this.
- **Plant a band or layout defect in the investor-type parser against `tests/server/shareholding/investor-type-parse-run.test.ts`.** Swapping `under5`/`atLeast5` in `typeColumns` (`src/server/holdings/investor-type.ts`) fails its backfill test in seconds; the header check alone does not catch it.
- **Never edit a migration a Preview has applied.** `scripts/applied-migrations.mts` holds the rule and its reasons, and `pnpm check` fails such an edit. It sees only this checkout's history, so when `gh pr checks` shows `kumora-dashboard-builds` failing, run `git diff <last passing>..HEAD -- apps/dashboard/*migrations/` first, then restore the file with `git checkout <last passing> -- <file>`.
- **The workerd suite is the `row-budgets` Vitest project.** From `apps/dashboard`, `pnpm exec vitest run --project row-budgets -t "move"` runs a busy day's move into alchemy's local R2 and compares every cold answer to the object's; an off-by-one tape block plant fails there as `Tape: expected {…} to deeply equal {…}`.
- **No Vitest constructs `TradingDayObject`.** Harnesses build the day value directly, so a plant inside the object class (such as reading `env` once at construction instead of through `WorkerEnv`) fails no test; it is held only by its field types and its `Decision:` pointer (`apps/dashboard/docs/adr/0106-the-trading-day-object-s-constructor-takes-no-bindings.md`). Record such a plant as untested, not as passing.
- **Judge a timing-test failure against staging, not by rerunning the branch.** `tests/lib/bubbles.test.ts` "stays under 2 ms for 900 codes" failed 3 of 3 on spec #517's branch at a load average near 10 (median 2.08 ms), then read 1.57–1.73 ms beside staging's 1.41–1.74 ms once the load fell. Check out `origin/staging` as a detached worktree under `~/.t3/worktrees/kumora/`, not the scratchpad: `pnpm install` there fails with exit 228 in `/tmp`, which is on another filesystem from the pnpm store. Run the test in both, back to back, with `-t "900 codes" --silent=false`, and compare the printed medians.
- **Plant cross-tab alert defects against `tests/components/book-alerts/use-book-alerts.test.tsx`.** Its `openTab` calls `vi.resetModules()`, so each tab gets its own modules over one shared localStorage and one fake Web Lock. A module-level store is therefore a real per-tab state, and a tab-local plant fails there in seconds.
- **Plant a restore read against the row budgets where it always runs.** The busy day in `row-budgets.workerd.test.ts` replays to no order flow events, so a defect inside `restore`'s `found` callback (`trading-day.ts`) never runs and passes. Plant the read at the top of `restoreOrderFlow` instead; reading every stored event there fails `expected 392582 to be at most 352594`.
- **Read Production's Workers Logs through the owner's Alchemy profile.** `~/.alchemy/profiles/default/cloudflare.json` holds an OAuth login with `workers-observability.read`. When it has expired, refresh it at `https://dash.cloudflare.com/oauth2/token` (`grant_type=refresh_token` with the profile's `clientId`) and write both new tokens back, since the refresh token rotates. Then POST `/accounts/<accountId>/workers/observability/telemetry/query` with `view: "events"` and a filter on `$metadata.service` = `kumora-dashboard`. Filters on `$workers.event.path` = `/ingest`, `$metadata.message` = `close` (with `$workers.event.code`) and `$workers.cpuTimeMs` find reconnects, socket closes and long turns. Issue #603 was settled this way.
- **A trading-day log line's time can be another event's.** The Worker's clock stands still while it computes, and Effect fibers forked from a timer log under whichever event is running. A close handler that runs while the :05 flush holds the turn therefore logs at the flush's instant. Many forked fibers' lines are never kept at all (the per-minute "Rows written" mostly don't appear). Use each event's `wallTimeMs` and `cpuTimeMs` rather than the log lines' times.
- **Removing the flush timer's yield between its two turns passes every test.** `armFlush` in `trading-day.ts` and ADR-0123 say why it is there. Record that plant as untested; only a Session 2 open on Staging shows it (#603).
- **`fuser -k <port>/tcp` stops only the listener of a hand-run `bun alchemy dev`.** The `bun alchemy dev` process and its `workerd` children stay, and a fresh `workerd` can appear seconds after you kill the rest. Find them with `pgrep -af "[w]orkerd"`, check each one's `readlink /proc/<pid>/cwd` is your worktree's `apps/dashboard` (other sessions run their own), kill them, and look again after a few seconds.
- **A local stage treats a changed D1 prop as an update.** Adding `primaryLocationHint` and `clone` showed `[AuthDb] update (local)` and kept the `dev:` id and its rows (#658). The local provider ignores both props. Check a local database's rows with `node:sqlite` through `databaseId` and `databaseFile` in `apps/e2e/support/local-d1.ts`.
- **A new `archive-migrations/*.sql` is invisible to Vitest the same way.** Spec #659's 0004 failed `pnpm check` with `no such table: run_import_window` until `pnpm exec vitest run --clearCache` from `apps/dashboard`. Planting an older tree that lacks a migration needs the same clear before and after.
- **Two `Decision:` pointers on one declaration need an empty `//` line between them.** Without it `scripts/check-decision-docs.mts` reads them as one four-line pointer and fails (spec #659, ArchiveDb in `alchemy.run.ts`).
- **A merge of staging can leave a PR conflicting while every local check passes.** GitHub runs no `pull_request` CI on a conflicting PR, so marking it ready starts nothing; `gh pr view <n> --json mergeable` shows `CONFLICTING` (spec #659, after #667 landed).
- **Plant a fix that spans several places one place at a time.** Spec #673's two-reports-in-a-month fix changed the derivation, the read's `selected` and Major holders' month rule; the read plant passes alone because the Monthly `periods` CTE also keeps only a month's newest report, and fails only with that guard reverted too. A heap plant fails in about 1 s with `-t` on one describe of `stock-page-heap.test.ts` or `holder-moves-heap.test.ts`.
- **A server render can overflow a Worker after its read fits.** Spec #673's Daily holders read fit 32 MiB at the caps, yet `renderToReadableStream` of the panel alone exhausted 128 MiB; lists of stored rows go through `BoundedRows` (ADR 0133), and the render heap tests in `stock-page-heap.test.ts` run React's edge server build in a Vite-bundled worker.
